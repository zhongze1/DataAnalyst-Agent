# 业务指标定义与口径

> 本文是 RAG 实验语料之一，为 **DataAnalyst Agent** 的 5 套业务测试数据集定义指标口径。
> **重要前提**：项目里**没有**任何预置的指标计算函数 —— 工具是通用的（按列聚合、透视、
> 沙箱执行 pandas 代码），具体指标一律由 Agent 用 `run_pandas` **现算**。
> 因此本文定义的是**数据口径**（用哪些列、按什么粒度、边界怎么处理），供 Agent 与人工核对使用。
>
> 本文事实来源：`data/samples/测试指南.md`（列名与关键真值）、数据生成脚本
> `data/samples/generate_business_datasets.py` 与核对脚本 `verify_datasets.py`、以及仓库代码。
> 凡无法从这些材料确认的，一律标注**待确认**。

## 0. 通用约定

- **金额单位**：元；**比例**：百分数（如 37.36%），计算时注意不要与 0.3736 混用。
- **粒度**：先确定"一行代表什么"，再决定分子分母 —— 这是绝大多数口径错误的根源。
  各数据集的粒度：门店/电商/SaaS 流水均为**行级交易**；SaaS 月度订阅为**月 × 套餐**；
  库存快照为**月末 × 门店 × SKU**。
- **缺失值**：pandas 里是 `NaN`，默认**不参与求和**（`sum()` 跳过 NaN），
  但**参与计数**时若用 `len()` 会得到错误分母 —— 涉及均值时必须显式用 `count()` 或 `dropna()`。
- **异常值**：5 套数据集都刻意埋入了 2~4 处业务异常（负值、重复主键、时序矛盾、越界评分等）。
  任何指标在给出数字时都应说明**是否已剔除异常**，两套口径同时给最好。

## 1. 销售额

**定义**：一定时间范围内、一定维度下的交易金额合计（不含退款/取消的部分需显式声明）。

| 数据集 | 金额列 | 行级粒度 | 备注 |
| --- | --- | --- | --- |
| 连锁门店销售 | `销售明细.销售额` | 一笔交易 | 有 `单价`、`折扣率` 列；销售额与"单价×数量×折扣"的换算关系**待确认**（可用 `run_pandas` 抽样验证） |
| 电商平台订单 | `订单明细.订单金额` | 一张订单 | 有 `销售数量`、`单价`、`折扣率`、`成本`、`毛利`；`订单状态` 含"已取消" |
| SaaS 订阅 | `账单流水.金额`（另见 `月度订阅.MRR`） | 一张账单 | `MRR` 是月度订阅口径的月度经常性收入，与账单流水口径**不同**，不可混用 |

**公式**（示例：按区域）

```
区域销售额 = Σ(销售额)  group by 区域
```

**统计粒度**：行级求和后按维度（区域/品类/门店/月份/会员等级）聚合。

**必须处理的边界**

1. **已取消 / 退款**：电商数据集 3600 笔订单中 **194 笔已取消**。
   测试指南给出的核对基准：**含已取消总额 9,655,364.21 元，剔除后 9,252,156.62 元**。
   任何"总销售额"都必须声明用的是哪个口径。
2. **负值**：门店数据集 `TX202400591`（销售数量 = -1，销售额为负）；
   SaaS `账单流水` 中 `BILL-202411-1319` 金额 = **-499.00**（退款）。
   负值既可能是退货也可能是脏数据，不能一律取绝对值。
3. **重复主键**：SaaS 的 `BILL-202410-0956`、电商的 `ORD2024002235` 各出现两次。
   **订单/账单级指标必须先按主键去重**，否则金额被重复计入。
4. **超大批量订单**：电商 `ORD2024000622`、`ORD2024002900` 的销售数量 = **800**
   （正常单量级为个位/十位），会显著抬高总额与按品类/月度的分布，
   建议单独标注或剔除后再看结构占比。

## 2. 利润率（毛利率）

**重要约束**：只有**电商平台订单**数据集同时具备 `成本` 与 `毛利` 列，因此**只有它能算利润率**。
其余 4 套数据集（SaaS、连锁门店、广告投放、客服工单）**都没有成本列**，无法计算利润率 ——
遇到此类提问应明确说明"数据中没有成本字段"，不要用其他列代替。

**定义**：毛利占销售金额的比例，反映每 1 元收入留下多少毛利。

**公式**

```
毛利率 = Σ毛利 / Σ订单金额 × 100%
其中  毛利 = 订单金额 − 成本          （毛利是数据集中的独立列，可用上式交叉校验）
```

**统计粒度**：订单级求和后按维度聚合（品类/会员等级/地区/月份）。
注意：**不能用"逐单毛利率再求平均"**，那会被小订单放大，不等价于整体毛利率。

**核对基准**（来自测试指南）

| 口径 | 值 |
| --- | --- |
| 剔除"已取消"后的订单金额 | 9,252,156.62 元 |
| 同口径毛利率 | **37.36%** |

**必须处理的边界**

1. **已取消订单**：其金额与毛利都无效，必须剔除（否则毛利率被稀释）。
2. **单笔负毛利**：可能存在（例如高折扣订单），会导致毛利率偏低；应统计负毛利单数并单独说明。
3. **异常大单**：`销售数量 = 800` 的两笔异常订单会明显抬高其所属品类的毛利率，
   按品类比较**必须同时给出剔除前后的两个口径**，否则结论会反转。
4. **成本录入异常**：若某些订单的 `成本` 明显偏离 `单价 × 销售数量` 的量级，
   应视为录入问题并提示（是否已确认存在此类问题：**待确认**）。

### 2.1 广告投放的对应指标：ROAS

广告数据集没有"利润"概念，等价指标是 **ROAS（广告消耗回报）**。列：`投放明细.消耗`、`投放明细.成交金额`。

```
ROAS = Σ成交金额 / Σ消耗
```

**核对基准**（来自测试指南）：总消耗 12,601,565.78 元、总成交 41,914,977.99 元 → **整体 ROAS 3.33**
（作者复核：两数相除 ≈ 3.326，与 3.33 一致）。

**边界**

1. **零消耗但有转化**：`2024-03-17 腾讯广告` 消耗 = 0 而转化 = 150。
   ROAS 的分母为 0 时**不可计算**，必须作为异常记录排除或单独标注（不能写成无穷大）。
2. **缺失值**：`成交金额` 缺 40 行、`广告组` 缺 15 行 —— 求 ROAS 时缺失行会被跳过，
   分母（消耗）却不缺，会**系统性低估**分子，需要在结论里说明覆盖率。

## 3. 客单价

**定义**：一个"客"贡献的金额。**这个词有两种常见口径，含义完全不同，必须声明用哪一种**：

| 口径 | 公式 | 分母（粒度） | 回答的问题 |
| --- | --- | --- | --- |
| ① 人均销售额 | Σ有效订单金额 / 有效**客户数** | 客户级（客户 ID 去重） | 平均每个下单客户花了多少钱 |
| ② 笔单价 | Σ有效订单金额 / 有效**订单数** | 订单级（订单号去重） | 平均每张订单多少钱 |

测试指南中的"人均销售额"就是**口径 ①**。核对示例（电商数据集，剔除已取消）：

```
普通会员：有效销售额 3,267,534.50 / 客户数 353 ≈ 9,256.47 元
```

（作者复核：两数相除 ≈ 9,256.19，与表中 9,256.47 的差异来自表中已按各自口径四舍五入，量级一致。）

**统计粒度**：先按客户或订单聚合出分子，再除以对应去重后的个数。

**必须处理的边界**

1. **分母到底是谁**：电商数据集共 700 名注册客户，但只有 **437 人**下过单。
   用"下单客户数(437)"还是"全部注册客户(700)"会产生完全不同的数字 —— 默认用下单客户数，且必须写明。
2. **去重**：重复订单号（`ORD2024002235`）与"一客多单"都要在对应口径下去重。
3. **已取消/退款**：与前两节同规则，默认剔除并声明。
4. **不要跨维度混用**：把"人均"和"笔均"混在一个对照表里比较，会得出错误结论。
5. **其他数据集的对应指标**：广告数据集可算 **CPA = Σ消耗 / Σ转化数**（单次获客成本，
   与"客单价"方向相反）；客服数据集无金额，**不适用**。

## 4. RFM 客户分层

**定义**：按三个维度刻画客户价值 —— R（最近一次消费距今多久）、F（消费频次）、M（消费金额）。

**数据来源**：电商数据集 `订单明细`（`客户ID`、`下单日期`、`订单金额`、`订单状态`）
＋ `客户主数据`（`客户ID`、`注册日期`、`会员等级`、`城市`、`地区`）。

**公式**（客户级，一位客户一行）

```
R = 基准日 − 该客户最后一次有效订单的下单日期       单位：天（越小越好）
F = 该客户有效订单数                               单位：笔（需按订单号去重）
M = 该客户有效订单金额合计                          单位：元
```

随后对 R/F/M 分别打分或分箱，再组合成分层标签（如"重要价值客户""重要挽留客户""新客/潜力""流失客户"）。

**统计粒度**：**客户级**（必须先聚合到客户，再分层）。

**必须处理的边界**

1. **基准日未定义（待确认）**：测试指南没有规定 R 的基准日。
   取"数据集最大下单日期"、"数据截止日 2024-12-31"还是"分析当天"，得到的 R 完全不同，
   分层结果也随之变化。**任何 R / 分层结论都必须连同基准日一起给出。**
2. **分箱阈值未定义（待确认）**：是按分位数（如各 20%）还是按均值切分、阈值为多少，
   测试指南均未给出。**因此"重要价值客户有多少人"这类结论在没有声明阈值时不可复现、不可比较。**
3. **有效订单口径**：已取消（194 笔）与退款中（100 笔）是否计入 F 与 M，
   会直接改变分层；必须声明，并建议给出两套口径的差异。
4. **F 的去重**：`ORD2024002235` 重复出现，按订单号去重后再计数。
5. **新客判定**：`客户主数据.注册日期` 与首次下单日期不一致时（先注册后长期未下单），
   "新客/潜力"的判定基准（按注册还是按下单）**待确认**。
6. **数据质量**：客户手机号存在缺失（打码规则会遮蔽该列）；订单的 `物流方式` 缺 72 行 ——
   与 RFM 本身无关，但同表分析时需要说明。

## 5. 其他常用派生指标（口径速查）

| 指标 | 公式 | 分母 / 粒度 | 边界 |
| --- | --- | --- | --- |
| 复购率 | 复购客户数 / 下单客户数 | 客户级 | 电商核对基准：≥2 单客户 **345 / 437**；去重订单号 |
| 人均订单数 | 有效订单数 / 下单客户数 | 客户级 | 电商核对基准：**8.24** 单/人（3600 / 437 ≈ 8.24 与之量级一致） |
| CTR | 点击量 / 曝光量 × 100% | 行级（日 × 渠道） | 存在"点击 > 曝光"的埋点异常 3 条，会让 CTR > 100% |
| CVR | 转化数 / 点击量 × 100% | 行级 | 点击量为 0 时不可计算 |
| CPA | 消耗 / 转化数 | 行级 | 转化数为 0 时不可计算 |
| 平均响应时长 | Σ响应时长_分钟 / 工单数 | 工单级 | 存在"响应时长 = 0"的逻辑异常 2 条 |
| 平均解决时长 | Σ解决时长_小时 / 工单数 | 工单级 | 存在"解决时长 < 响应时长"的时序异常 3 条 |
| 满意度均值 | Σ满意度评分 / **有评分的记录数** | 工单级 | 2600 条工单中**仅 1385 条有评分**（未解决工单不回填）；分母若误用 2600 会严重失真。另有越界评分 6 分的异常 1 条 |
| 客户流失率（SaaS） | 流失客户 / 期初客户数 | 月 × 套餐 | `月度订阅` 存在一行不平（期末 ≠ 期初 + 新增 − 流失，差 7），必须先校验自洽性 |
| 库存健康度 | 库存量 < 安全库存 的记录数 / 总记录数 | 月末 × 门店 × SKU | 核对基准：**228 / 1440**；存在周转天数 = 999 的占位异常 |

## 6. 边界处理总则（给分析者的检查清单）

1. **先声明口径**：时间范围、维度、含不含取消/退款/异常、分母是谁 —— 这四项缺一项，数字就不可比。
2. **异常三问**：有没有负值？有没有重复主键？有没有数量级离谱的记录？
3. **两套口径**：剔除异常前 / 后各给一次，并说明差异原因（例如按品类看毛利率时结论可能反转）。
4. **分母陷阱**：缺失值会缩小分母（或用错分母），凡涉及"率"与"均值"必须显式写下分母定义。
5. **核对习惯**：关键结论应与 `data/samples/verify_datasets.py` 的输出对照；
   脚本用固定随机种子生成数据，输出可作为核对基准。

## 7. 待确认清单（本文档中无法从现有材料确认的点）

1. 门店数据集中 `销售额` 与 `单价 × 销售数量 × 折扣率` 的精确换算关系；
2. 电商数据集中是否存在 `成本` 按单件（而非按订单）记录的录入问题；
3. RFM 的 **R 基准日**；
4. RFM 的**分箱方式与分层阈值**（分位数 / 均值 / 固定阈值）；
5. "新客/潜力"客户的判定基准（注册日期优先还是首次下单日期优先）；
6. 广告数据集 `成交金额` 缺失 40 行的成因，以及在 ROAS 计算中应如何处置（跳过 / 视为 0 / 剔除整行）。
