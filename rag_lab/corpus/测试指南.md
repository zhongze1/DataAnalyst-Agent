# 业务测试数据集 · 使用指南

> 为 **DataAnalyst Agent** 准备的 5 套模拟真实公司业务的 Excel 测试集。
> 全部由 `generate_business_datasets.py` 用固定种子（20240614）生成，结果可复现。
> 本文件中的**所有数字**均由 pandas 工具链实算，与 Agent 的 `run_pandas` 走同一套 pandas 逻辑，可直接用于核对 Agent 回答是否正确。

---

## 为什么是 5 个独立文件

`app/agent/prompts.py` 明确说明 Agent 是**单表分析**（切换工作表时 `df` 被整体替换，不支持跨表 join）。因此每个业务场景做成一个独立 Excel（各自上传 = 一个独立 session），覆盖 5 种不同的分析范式：

| # | 文件 | 业务场景 | 分析范式 | 行数 | 工作表 |
| --- | --- | --- | --- | --- | --- |
| 1 | `SaaS订阅业务_2024.xlsx` | SaaS 公司 | 趋势 / MRR / 流失 | 1956 | 客户明细 / 月度订阅 / 账单流水 |
| 2 | `连锁门店销售_2024.xlsx` | 20 家连锁门店 | 多店对比 / 区域透视 | 4660 | 销售明细 / 门店信息 / 库存快照 |
| 3 | `广告投放数据_2024.xlsx` | 广告投放团队 | 漏斗 / ROAS / 效率 | 1218 | 投放明细 / 渠道基础 |
| 4 | `客服工单_2024.xlsx` | 客服中心 | 时长 / SLA / 满意度 | 2614 | 工单明细 / 客服人员 |
| 5 | `电商平台订单_2024.xlsx` | 电商平台 | RFM / 复购 / 品类 | 4332 | 订单明细 / 商品主数据 / 客户主数据 |

每个数据集都**刻意埋入了 2~4 处业务异常**，用于检验 Agent 的「风险提示」能力（`prompts.py` 要求它"发现异常、缺失、偏态时主动提示"）。

**怎么测**：把其中一个 xlsx 拖进左侧上传区，再逐条提下面的"建议提问"，把 Agent 的回答与本文的"关键真值 / 埋入异常"对照。

## 1. SaaS订阅业务_2024.xlsx

**场景**：一家 SaaS 公司 2024 年的客户档案、月度订阅指标与账单流水。

**表结构**
- `客户明细`（420 行）：客户ID / 客户名称 / 注册日期 / 套餐 / 月费 / 客户状态 / 行业 / 城市 / 地区
- `月度订阅`（36 行 = 12 月 × 3 套餐）：月份 / 套餐 / 期初客户数 / 新增客户 / 流失客户 / 期末客户数 / MRR
- `账单流水`（1500 行）：账单号 / 客户ID / 客户名称 / 账单月份 / 套餐 / 金额 / 支付状态 / 支付方式

**关键真值（用于核对）**

| 指标 | 值 |
| --- | --- |
| 客户总数 | 420（活跃 341 / 已流失 79） |
| 套餐分布 | 基础版 235 / 专业版 139 / 企业版 46 |
| 行业 Top3 | 互联网 99 / 金融 63 / 制造业 59 |
| 12 月 MRR 合计 | **174,446.00** 元 |
| 12 月期末客户数合计 | 354 |
| 账单总额 | **665,102.00** 元 |
| 支付状态分布 | 已支付 1272 / 待支付 155 / 已逾期 72 / 已退款 1 |

**埋入异常**
- **退款账单**：`BILL-202411-1319`，金额 = **-499.00**（负值）
- **重复账单号**：`BILL-202410-0956` 出现两次
- **订阅表内部不平**：`2024-11 / 企业版` 一行，`期末客户数(59) ≠ 期初(42)+新增(12)-流失(2)=52`，差 7

**建议提问**
1. 客户一共多少？按套餐怎么分布？
2. 各套餐这几年的月度流失情况如何？年末 MRR 是多少？
3. 账单里有没有收款异常？
4. 月度订阅表的数据是否自洽（期初+新增-流失 = 期末）？

## 2. 连锁门店销售_2024.xlsx

**场景**：20 家分布在全国的连锁门店，2024 年销售流水与月末库存快照。

**表结构**
- `销售明细`（3200 行）：交易号 / 日期 / 门店ID / 门店名称 / 城市 / 区域 / SKU / 商品名称 / 品类 / 销售数量 / 单价 / 折扣率 / 会员 / 销售额
- `门店信息`（20 行）：门店ID / 门店名称 / 城市 / 区域 / 门店类型 / 开业日期 / 营业面积 / 店长
- `库存快照`（1440 行 = 12 月末 × 20 店 × 6 SKU）：快照日期 / 门店ID / SKU / 库存量 / 安全库存 / 周转天数

**关键真值**

| 指标 | 值 |
| --- | --- |
| 总销售额 | **4,440,228.47** 元 |
| 区域销售额 | 华中 1,854,124.60 / 华东 1,293,566.91 / 西南 777,638.59 / 西北 289,559.59 / 华南 225,338.78 |
| 品类销售额 | 家用电器 3,331,491.12（占比 75%）/ 美妆个护 491,117.48 / 服饰鞋帽 487,677.87 |
| 库存 < 安全库存 的记录数 | 228 / 1440 |

**埋入异常**
- **负销售额**：`TX202400591`（销售数量 = -1，销售额为负）
- **日期早于开业**：`TX202400008` 日期为 **2017-06-01**，但所属门店「重庆社区店01」开业日期是 **2019-10-06**——销售不可能早于开业
- **极端周转天数**：`ST006 / SKU0019` 周转天数 = **999** 天（明显是占位/录入错误）

**建议提问**
1. 总销售额是多少？按区域怎么分布？
2. 哪个品类卖得最好？
3. 数据里有没有明显异常的交易？
4. 库存健康度怎么样？有多少低于安全库存？

**表结构**
- `投放明细`（1218 行）：日期 / 渠道 / 广告组 / 曝光量 / 点击量 / 转化数 / 消耗 / 成交金额
- `渠道基础`（6 行）：渠道 / 开户时间 / 结算方式 / 负责人 / 返点比例

**关键真值**

| 指标 | 值 |
| --- | --- |
| 总消耗 | **12,601,565.78** 元 |
| 总成交金额 | **41,914,977.99** 元 |
| 整体 ROAS | **3.33** |
| 日期覆盖 | 2024-01-01 ~ 2024-11-24 |

**各渠道效率（按 ROAS 降序）**

| 渠道 | 消耗 | 成交 | ROAS | CTR% | CVR% | CPA |
| --- | --- | --- | --- | --- | --- | --- |
| 腾讯广告 | 1,511,261 | 7,736,162 | 5.12 | 3.53 | 1.97 | 60.5 |
| 百度广告 | 2,028,111 | 8,707,456 | 4.29 | 2.75 | 2.39 | 74.7 |
| 知乎 | 931,109 | 3,443,558 | 3.70 | 3.04 | 2.21 | 85.6 |
| 巨量引擎 | 2,676,274 | 9,571,164 | 3.58 | 3.49 | 2.08 | 86.4 |
| B站 | 1,494,777 | 4,417,794 | 2.96 | 5.61 | 1.10 | 101.2 |
| 小红书 | 3,960,033 | 8,038,843 | 2.03 | 4.76 | 1.77 | 146.6 |

**埋入异常**
- **点击量 > 曝光量**（业务上不可能，埋点异常）3 条：`2024-03-01 腾讯广告`、`2024-11-12 百度广告`、`2024-07-22 B站`
- **零消耗但有转化**：`2024-03-17 腾讯广告`（消耗 = 0，转化 = 150）
- **缺失值**：`广告组` 缺 15 行，`成交金额` 缺 40 行

**建议提问**
1. 各渠道的 ROAS 是多少？哪个渠道效率最高、最该砍？
2. 整体的转化漏斗（曝光→点击→转化）是什么样？CTR、CVR 各多少？
3. 数据里有没有不可能的记录？
4. 消耗和成交金额之间的关系如何？

## 4. 客服工单_2024.xlsx

**场景**：客服中心 14 名客服、2600 条工单的处理时长、状态与满意度。

**表结构**
- `工单明细`（2600 行）：工单号 / 创建时间 / 客户ID / 工单类型 / 优先级 / 来源渠道 / 客服ID / 客服姓名 / 所属组 / 工单状态 / 响应时长_分钟 / 解决时长_小时 / 满意度评分 / 是否升级 / 客户留言
- `客服人员`（14 行）：客服ID / 客服姓名 / 所属组 / 入职日期 / 职级

**关键真值**

| 指标 | 值 |
| --- | --- |
| 工单总数 | 2600 |
| 状态分布 | 已解决 1825 / 处理中 331 / 已关闭 299 / 待跟进 145 |
| 类型分布 | 咨询 889 / 退换货 510 / 技术支持 458 / 投诉 426 / 账单问题 317 |
| 平均响应时长 | **19.1** 分钟 |
| 平均解决时长 | **7.83** 小时 |
| 已解决/已关闭占比 | 81.7% |
| 满意度均值 | 3.97（仅 1385 条有评分，未解决工单不回填满意度） |

**埋入异常**
- **未解决却有满意度评分**（逻辑矛盾）5 条：`TK202400821`、`TK202401045`、`TK202401197`、`TK202402131`、`TK202402167`
- **越界评分**：`TK202401197` 满意度 = **6**（评分域应为 1~5）
- **解决时长 < 响应时长**（时序错误）3 条：`TK202400531`、`TK202402190`、`TK202402330`
- **响应时长 = 0**（秒级响应不现实）2 条：`TK202400098`、`TK202402559`

**建议提问**
1. 平均响应时长和解决时长是多少？处理效率如何？
2. 哪类工单最多？不同客服的工作量分布如何？
3. 满意度评分平均多少？满意度和工单类型有关吗？
4. 数据里有没有逻辑上说不通的记录？

## 5. 电商平台订单_2024.xlsx

**场景**：电商平台 700 名客户、3600 笔订单，含商品与客户主数据（可用于 RFM 分析）。

**表结构**
- `订单明细`（3600 行）：订单号 / 下单日期 / 客户ID / 客户姓名 / 会员等级 / 地区 / 商品ID / 商品名称 / 品类 / 销售数量 / 单价 / 折扣率 / 支付方式 / 订单状态 / 物流方式 / 订单金额 / 成本 / 毛利
- `商品主数据`（32 行）：商品ID / 商品名称 / 品类 / 标准售价 / 成本价 / 供应商 / 上架日期
- `客户主数据`（700 行）：客户ID / 客户姓名 / 注册日期 / 会员等级 / 城市 / 地区 / 手机号

**关键真值**

| 指标 | 值 |
| --- | --- |
| 订单总数 | 3600（下单客户 437） |
| 总订单金额 | 9,655,364.21 元（含已取消） |
| 剔除「已取消」后金额 | **9,252,156.62** 元，毛利率 **37.36%** |
| 订单状态 | 已完成 2582 / 已发货 478 / 待发货 246 / 已取消 194 / 退款中 100 |
| 品类销售额 Top3 | 手机数码 3,944,904 / 家用电器 2,040,683 / 家居家装 1,444,299 |
| 复购客户（≥2 单） | 345 人 / 437 人，人均 8.24 单 |

**会员等级的人均差异（重要分析点，口径：剔除已取消订单）**

| 会员等级 | 客户数 | 有效销售额 | 人均销售额 |
| --- | --- | --- | --- |
| 普通 | 353 | 3,267,534.50 | 9,256.47 |
| 银牌 | 194 | 2,712,742.65 | 13,983.21 |
| 金牌 | 114 | 1,797,468.33 | 15,767.27 |
| 钻石 | 39 | 1,474,411.14 | **37,805.41** |

> ⚠️ 这是个**陷阱式分析点**：若只看「总销售额」，会得出"普通会员贡献最大"的误导结论；但看「人均」，高等级会员的消费力是普通会员的 4 倍以上。好的 Agent 应该两个口径都提。

**埋入异常**
- **超大批量订单**（疑似企业团购 / 刷单）：`ORD2024000622`、`ORD2024002900`（销售数量 = 800）
- **重复订单号**：`ORD2024002235` 出现两次
- **已取消订单仍有金额**：194 笔已取消订单的金额应视作无效
- **缺失值**：物流方式缺 72 行；客户手机号有缺失

**建议提问**
1. 总订单金额和毛利是多少？毛利率如何？
2. 哪个品类卖得最好？
3. 客户复购情况怎么样？能不能做 RFM 分群？
4. 不同会员等级的消费能力有差异吗？
5. 数据里有没有异常或需要剔除的记录？

## 复现与校验

```bash
# 重新生成全部数据集（覆盖写入）
python generate_business_datasets.py

# 用项目工具链核对关键指标（可随时重跑）
python verify_datasets.py
```

生成脚本用固定随机种子，每次运行结果完全一致。若修改了脚本逻辑，`verify_datasets.py` 的输出即为新的核对基准。
