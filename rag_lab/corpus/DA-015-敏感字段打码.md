# DA-015: 敏感字段打码（PRD W2-4）

- **类型**: Feature
- **优先级**: P1（隐私）
- **预估工时**: 4 小时
- **前置依赖**: W2-2（导出与产物落盘，已建立脱敏钩子）、DA-007（双通路先例）

## 描述

**用户故事**：作为部署方，报表里含手机号、身份证这类个人信息。我要保证**任何对外可见的
出口**（聊天界面、导出报告、落盘产物）都不出现明文，同时**不能影响分析质量** ——
喂给模型的数据必须是原文，否则「按手机号去重」这类分析会被打码值直接算错。

**现状证据**（核实于本次接单）：
1. `app/security/redact.py:18,21` 的 `PATTERNS` 与 `SENSITIVE_COLUMNS` **都是空集**，
   三个函数（`redact_text` / `redact_frame` / `redact_value`）当前全是恒等
   —— W2-4 只有钩子，没有规则。
2. 钩子只接在**导出侧**（`app/storage/artifacts.py:143`、`app/services/export_service.py:52,64,183,234`），
   **展示层完全没接**：`steps[].result`（工具原始输出）、`steps[].arguments`、结论 `answer`
   都会原样出现在界面上（`app/web/static/app.js:210` 直接渲染 `s.result`）。
3. 导出的「执行轨迹」也漏了：`export_service.py:206,256` 取的就是 `step["result"]` 原文，
   而它来自落库的 `steps_json`（`loop._save` → `save_turn`），从未脱敏。
4. 落库的 `steps_json` 是历史明文，历史会话即使代码修好，导出仍会带出原文。

**做什么**（三层，一次改到位）：
1. **填规则**：内置手机号 / 身份证 / 银行卡 / 邮箱四条正则（保留部分可读位），
   以及内置列名关键词集合（手机、电话、身份证、证件、银行卡、卡号、邮箱、email、地址、住址、薪资、工资）。
2. **补展示层**：在 Agent Loop 的统一出口把 `steps[].arguments`、`steps[].result`、
   结论 `answer` 脱敏 —— 一处改动同时覆盖非流式响应、SSE `done` 事件与落库轨迹。
3. **补导出轨迹**：导出时对轨迹摘要**再次**脱敏（覆盖 DA-015 之前落库的历史明文）。
4. **配置化**：`AGENT_REDACT_ENABLED`（总开关，默认开）、`AGENT_REDACT_COLUMNS`
   （**追加**到内置默认集，默认空）。

**不做什么**：
- **不对模型脱敏**（双通路，同 DA-007）：`registry.run` 之后喂给模型的 tool 消息保持原文。
- 不改沙箱、不动工具层。
- 不做「自定义正则」（正则从环境变量注入有非法/ReDoS 风险，规则属于代码）。
- 不做流式增量的实时打码（见「已知限制」）。

## 验收标准（Given-When-Then）

### 一、文本规则

1. **Given** 一段含 11 位手机号的文本（示例 `13800138000`），**When** 过 `redact_text`，
   **Then** 保留前 3 后 4 变成 `138****8000`（PRD 要求的 `138****8888` 即此格式在
   号码以 8888 结尾时的表现）。
2. **Given** 18 位身份证（末位可能为 X），**When** 过 `redact_text`，
   **Then** 变成 `110101********123X` 形式（保留前 6 后 4）。
3. **Given** 16–19 位银行卡号，**When** 过 `redact_text`，**Then** 保留前 4 后 4，中间打星。
4. **Given** 邮箱地址，**When** 过 `redact_text`，**Then** 首字符与域名可见，其余打星。
5. **Given** 一串 13 位纯数字（既不是手机号也不是身份证），**When** 过 `redact_text`，
   **Then** **原文不变**（前后数字边界必须生效，不允许把长串的一部分当手机号打码）。
6. **Given** 不含敏感片段的普通文本或空串，**When** 过 `redact_text`，**Then** 原文返回，不抛异常。

### 二、列级规则

7. **Given** 列名命中关键词（如「手机号」）且值能匹配正则，**When** 过 `redact_frame`，
   **Then** 该列值保留前 3 后 4（`13800138000` → `138****8000`）。
8. **Given** 列名命中关键词但值匹配不上任何正则（如残缺的 `1101011990...`），
   **When** 过 `redact_frame`，**Then** 该值**整体**变成 `***`
   —— 列名已经声明它敏感，宁可比正则更保守。
9. **Given** 列名**未**命中但值里含手机号（文本列），**When** 过 `redact_frame`，
   **Then** 该单元格按正则打码（内容级兜底）。
10. **Given** 数值列（如「销售额」），**When** 过 `redact_frame`，**Then** 值不变
    （不能因为内容级规则误伤数字）。
11. **Given** 手机号被读成 int64 的列（列名命中），**When** 过 `redact_frame`，
    **Then** 仍然被打码（列名规则必须能兜住数值型）。
12. **Given** 列里混有缺失值，**When** 过 `redact_frame`，**Then** 缺失值保持缺失（不被写成 `***`）。
13. **Given** 配置了 `AGENT_REDACT_COLUMNS=工号`，**When** 过 `redact_frame`，
    **Then** 「工号」列被打码，且**内置默认集仍然生效**（配置是追加，不是覆盖）。
14. **Given** `AGENT_REDACT_ENABLED=false`，**When** 过上述任意函数，**Then** 全部恒等。

### 三、双通路（核心不变量）

15. **Given** 工具输出含手机号，**When** 一次提问结束，
    **Then** 对外的 `steps[].result` **不含**明文，但**喂给模型的 tool 消息含明文**
    （用捕获型 LLM 桩断言两侧）。
16. **Given** 工具参数里含手机号（例如 `run_pandas` 的代码里写死了手机号），
    **When** 检查对外的 `steps[].arguments`，**Then** 不含明文（正则打码）。
17. **Given** 模型把手机号写进了结论，**When** 检查响应 `answer`，**Then** 已打码。
18. **Given** 上一轮的 assistant 原文含手机号，**When** 检查 `session.messages`（喂给下一轮模型的上下文），
    **Then** 仍是**原文**（脱敏只对外，不能污染模型的历史上下文）。

### 四、导出与产物

19. **Given** 一个含手机号的 DataFrame 产物，**When** 落盘后读回，**Then** 已是打码值（`138****8888`）。
20. **Given** 历史会话（`steps_json` 里是 DA-015 之前落库的**明文**），
    **When** 导出 Markdown 与 Excel，**Then** 「执行轨迹」里**不含**明文（导出侧二次脱敏兜底）。
21. **Given** 导出「数据明细」sheet，**When** 检查内容，**Then** 与产物一致（已打码）。

### 五、配置与回归

22. **Given** 未新增任何环境变量，**When** 启动服务，**Then** 配置校验通过、打码默认开启
    （升级不会因为新配置起不来）。
23. **Given** `AGENT_REDACT_COLUMNS` 用中文逗号/分号/空白分隔，**When** 解析，**Then** 均能正确切分。
24. **Given** 全部改动完成，**When** 运行 `uv run python -m pytest -q`，**Then** 原有用例与新用例全绿。

## 备注（关键设计决策）

1. **脱敏只对外**（双通路）：`registry.run` 的返回值原样喂给模型，
   只在**构造对外内容**时打码。若图省事在工具层打码，模型会拿着 `138****8888` 去
   groupby，分析结果直接错 —— 这是本工单最重要的一条边界。
2. **展示层只改一处**：`loop.py` 构造 `ToolStep` 与 `_finish` 收尾。
   由于 `steps` 同时是「SSE done 事件 / 非流式响应 / 落库轨迹」的同一个来源，
   一处改动即可覆盖三个出口，且顺带把历史轨迹的落库内容也变成打码值。
3. **脱敏在漂移检测之后**：`_finish` 里先做 `detect_task_drift`（它要拿模型真实输出的原文
   去比对提问关键词），最后一步才替换 `answer`。
4. **列名规则比正则更关键**：`redact_frame` 的文本规则只作用于 object 列
   （`redact.py:46`），手机号被读成 int64 时正则无从下手，只有列名能兜住。
   因此配置是**追加**语义（不允许覆盖默认集），避免配错就把兜底规则全丢掉。
5. **`PATTERNS` / `SENSITIVE_COLUMNS` 是模块级可变全局**：既有测试直接 `add`/`discard`/`clear`
   它们，会造成跨用例污染（已修的 2 条就是这个问题），新用例一律用 `monkeypatch`。

## 已知限制

1. **流式增量不脱敏**：SSE 逐字推送时无法在 token 边界打码（手机号会被切成若干 token）。
   落定后 `done` 事件会用脱敏版整体替换气泡内容（`app.js` 的 `case "done"` 会重写 `innerHTML`），
   即**只在生成过程中的几秒内可能短暂出现明文**。彻底解决需要「滚动缓冲 N 字符再下发」，
   复杂度和体验代价都更高，本工单不做。
2. **正则可能漏**：比如中间带空格/短横线的手机号（`138 0013 8000`）不会命中；
   未命中时列名规则会兜住（整体 `***`），但如果**列名也不敏感**，该值就不会被打码。
3. **打码不可逆**：产物 CSV 落盘即打码，导出「数据明细」也来自它 —— 这是有意的，
   原始值只在原始 Excel 文件与会话上下文中。

### 顺带修复的既有缺陷（在本工单范围内，非扩大改动）

`redact_frame` 的内容级规则用 `dtype == object` 判断文本列。本项目跑的是
**pandas 3.0.6**，字符串列默认 dtype 是 `str`（`StringDtype`），
`dtype == object` 对它**恒为 False** —— 也就是说**内容级兜底一直是死代码**：

- 规则为空时完全看不出来（反正全是恒等）；
- 一旦填上规则而不修这里，就会出现「列名不敏感的列（如备注）里的手机号漏出去」，
  而这正是最容易被漏掉的一类泄露。

已改为显式判据 `_is_text_column()`（`StringDtype` 或 `object`），并在注释里写明踩坑经过。
发现它的用例是 `test_non_sensitive_text_column_gets_content_level_masking`。

### 既有测试的适配（3 条，均在 `tests/test_export.py`）

1. `test_redact_is_identity_by_default` → 更名 `test_artifact_is_masked_on_save`：
   该用例原本断言「W2-4 还没做，当前必须是恒等」，DA-015 完成后必然要改，
   现在断言落盘产物是 `138****8000`。
2. `test_redact_frame_masks_by_column_name`：原本直接 `SENSITIVE_COLUMNS.add/discard`
   模块级全局。默认集里就有「身份证」，`discard` 会把它**永久删掉**并污染后续用例
   （顺序依赖）。已改为 `monkeypatch`。
3. `test_redact_text_applies_patterns`：原本 `PATTERNS.clear()` 收尾，同样会**清空内置规则**。
   已改为 `monkeypatch`。
