# eval · 检索评估（RAG-04）

> **草稿，等你审核**：题目由我起草（依据现有 6 份语料），请直接改 `questions.jsonl`。

## 文件

| 文件 | 用途 |
| --- | --- |
| `questions.jsonl` | 评估题 + 标准答案标注，一行一个 JSON 对象 |
| `report.md` | 评估结果（**由脚本生成，不要手改**） |

## 题目字段

| 字段 | 含义 |
| --- | --- |
| `qid` | 题号（`Q..` 计分，`T..` 陷阱题不计分） |
| `question` | 提问原文（检索时就拿它当 query） |
| `expect_doc` | 最该命中的文档（不含 `.md`） |
| `also_ok_docs` | **也接受**的文档：这些文档同样含正确答案，命中它们不算错 |
| `expect_section` | 期望命中的章节（`*` 表示该文档没有固定章节，或答案分散在多节） |
| `answer_contains` | 标准答案里**必须出现**的字符串（用来判定"这条召回有没有真正回答问题"） |
| `type` | 题目类型：口径 / 分母陷阱 / 架构 / 安全 / 数据 / 能力 / 行为契约 / 设计决策 / 陷阱题 |
| `scored` | 是否计入 recall@k 与 MRR（陷阱题为 `false`） |
| `note` | 判分时的人话说明（例如"只说一种口径算不完整"） |

## 判定规则

一次命中（hit）的定义是**内容级**的，不看排名之外的任何东西：

```
top-k 片段里存在一条，满足：
  (1) 它来自 expect_doc 或 also_ok_docs 中的任一文档，且
  (2) 它的文本包含 answer_contains
```

用 `also_ok_docs` 是因为语料本身有重叠：例如 `9,252,156.62` 这个核对基准
**同时**写在 `指标定义.md` 和 `测试指南.md` 里 —— 严格只认一份文档会把"正确的召回"
判成漏召回。这是刻意的宽松，不是放水。

指标：

- **recall@k**：18 道计分题里有多少题在 top-k 内命中；
- **MRR**：在命中的题上取 `1/排名` 的均值，衡量"命中得有多靠前"；
- **三种检索方式分开算**：向量 / 关键词（字符 2-gram）/ 混合，各自独立出一份数字，
  便于比较（本轮只评估，不做融合调参）。

## 陷阱题（T01 / T02）怎么用

它们**不计入** recall：语料里根本没有答案，检索器总会返回点什么。
它们的价值在 RAG-05（接进 Agent 之后）——观察模型会不会拿不相干的片段
自信编出"多 worker 限流方案"或"2023 年销售额"。现在只记录**返回的最高分**，
分数越低越好（分数高说明检索器在无答案的问题上也很自信，是风险信号）。

## 怎么跑

```powershell
uv run python -m rag_lab.evaluate            # 三种方式全跑，写 eval/report.md
uv run python -m rag_lab.evaluate --k 10     # 换个 k
uv run python -m rag_lab.evaluate --mode keyword   # 只跑关键词
```

首次运行会对 20 个 query 各调一次向量服务（20 条文本，费用可忽略）；
**query 向量会进缓存**（单独的空间），所以重复跑不重复计费。
