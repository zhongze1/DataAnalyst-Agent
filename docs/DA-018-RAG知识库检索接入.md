# DA-018：RAG 知识库检索接入（把检索注册成 Agent 工具）

> 类型：Feature　|　复杂度：🟡 中　|　状态：**待办**
> 前置：RAG-01~04（`rag_lab/`，独立子工程，已完成且评估达标）

## 背景

`rag_lab/` 已经做到：语料分块（73 片）、向量化（text-embedding-v4，1024 维）、
三种检索（向量 / 字符 2-gram BM25 / RRF 混合）以及 20 题评估。
评估结果（`rag_lab/eval/report.md`）：

| 方式 | recall@5 | MRR |
| --- | --- | --- |
| vector | 0.944 | 0.770 |
| keyword | 0.944 | 0.835 |
| **hybrid** | **1.000** | **0.858** |

进 RAG-05 的闸门（`recall@5 ≥ 0.9` 且每条召回能解释原因）**已满足**。
本工单把它接进主工程，让 Agent 能"查项目自己的文档"回答问题。

## 架构决策（本工单的核心）

**rag_lab 是构建与评估工具，主工程是运行时服务；两者之间的接口是"一个数据文件"，不是代码。**

理由：两个子工程的 venv 与依赖完全分开（`rag_lab` 甚至有自己的 `.venv`），
主工程必须能**独立部署**（不能要求部署机上有 lab 的虚拟环境）。

```
rag_lab（构建期）                        主工程（运行期）
corpus/*.md ──分块──> chunks.jsonl         app/services/knowledge_service.py
                      │                     · 读 data/knowledge/ 下的工件
                      └──向量化──> 缓存      · 余弦 + 2-gram BM25 + RRF（同一套公式）
                                   │         · 查询向量：可选（见下）
                            导出 ──┴──> data/knowledge/knowledge_index.jsonl
                                        data/knowledge/manifest.json
```

### 关键取舍

1. **不 import `rag_lab`**，主工程内重写约 150 行运行时检索（纯 Python + math，**零新依赖**）。
2. **查询向量化是可选的**：新增 `AGENT_EMBEDDING_*`（base_url / api_key / model / timeout / trust_env）。
   - 配了 → 混合检索（向量 + 关键词）；
   - 没配 → **自动降级为纯关键词**，并且**在工具返回里明确写出当前模式**；
   - 所有新配置都有默认值，**升级后不会因为缺配置起不来**（沿用 DA-017 的配置纪律）。
3. **维度/模型一致性校验**：`manifest.json` 记录 `space / model / dim`；
   查询向量维度与工件不一致时**降级为关键词模式并告警**，绝不拿不同模型的向量硬比。
4. **知识库未构建时要明说**：工件不存在 → 工具返回"知识库未构建（请先跑 rag_lab 的导出）"，
   而不是假装检索不到。
5. **复用既有设施，不新造轮子**：注册进 `ToolRegistry` → 自动获得工具审计（DA-008）；
   输出进 `steps[].result` → 自动被 DA-015 打码；请求级配额与并发（DA-017）自动生效。

## 验收标准（Given-When-Then）

### A. 构建与工件

1. **Given** `rag_lab/` 已有分块与向量，**When** 跑导出命令，**Then** 生成
   `data/knowledge/knowledge_index.jsonl`（一行一个片段，含 `text` 与 `vector`）
   与 `manifest.json`（空间、模型、维度、片段数、语料文件哈希、生成时间）。
2. **Given** 有片段缺向量，**When** 导出，**Then** 报错并**不生成半截索引**
   （manifest 记录缺失数量），退出码非 0。
3. **Given** 语料文件被改动，**When** 重新导出，**Then** manifest 里的语料哈希随之变化
   （用于识别"知识库是哪一版"）。

### B. 运行时检索

4. **Given** 工件存在且配置了 embedding，**When** 提问，**Then** 返回混合检索的 Top-K，
   每条带 `doc_id / section / 行号 / 分数 / why`（为什么召回）。
5. **Given** 未配置 embedding（或未提供 Key），**When** 提问，**Then** 降级为纯关键词检索，
   **且返回内容里明确标注"关键词模式"**。
6. **Given** 查询向量维度与工件不一致，**When** 提问，**Then** 降级为关键词模式并告警
   （不抛错、不影响回答）。
7. **Given** 工件不存在或损坏，**When** 提问，**Then** 返回明确的"知识库未构建/不可用"提示，
   **不抛异常打断 Loop**（沿用工具层"永不抛异常"的既有约定）。
8. **Given** 提问与语料完全无关，**When** 检索，**Then** 返回空结果，
   并提示"知识库中没有相关内容"，**不返回低分噪声**（设最低分阈值）。

### C. 接入 Agent

9. **Given** 工具已注册，**When** 请求工具 schema，**Then** 工具名与参数（`query`、`top_k`）
   出现在 `openai_schemas()` 中，且 `top_k` 有上限。
10. **Given** 系统提示词，**When** 已启用知识库，**Then** 提示词包含该工具的用法与顺序要求
    （查项目文档类问题优先用它），并有测试断言这一点。
11. **Given** 一次会话提问，**When** 模型调用该工具，**Then** 调用记录出现在审计 JSONL 中
    （只记形状，不记内容），且步骤结果里**不出现**未脱敏的敏感值（DA-015 生效）。
12. **Given** 配额已耗尽，**When** 提问，**Then** 仍然走 429（DA-017 不受本工单影响）。

### D. 配置与兼容

13. **Given** 一份旧 `.env`（不含任何新增键），**When** 启动，**Then** 校验通过、服务可用，
    知识库工具默认**可用**（读默认路径），embedding 未配置时按关键词模式工作。
14. **Given** `AGENT_KNOWLEDGE_ENABLED=false`，**When** 请求工具 schema，
    **Then** 工具不注册（并且提示词里也不提它）。
15. **Given** 新增配置项取值非法（例如 `top_k=0`），**When** 启动，**Then** 配置校验报错并给出修复建议。

### E. 质量与回归

16. **Given** 本工单完成后，**When** 跑主工程全量测试，**Then** 原有 488 条全部通过。
17. **Given** 新增测试，**When** 跑它们，**Then** 全程**离线**（不发真实网络请求），
    且文件系统操作只落在 `tmp_path`。
18. **Given** 用真实知识库做一次端到端提问，**When** 问到语料里确实写过的问题，
    **Then** 回答里包含正确来源（文档 + 章节）且内容与语料一致。

## 不做的事（明确边界）

- 不把 `rag_lab` 变成主工程的依赖（不改根 `pyproject.toml` 的依赖图）；
- 不做向量数据库（73 个片段用内存 + 纯 Python 足够；量级上来再说）；
- 不做多轮/对话式检索改写；不做 rerank 模型；
- 不追求多 worker 部署（沿用 DA-017 的单进程假设）。

## 已知限制

1. 知识库工件放在 `data/` 下，而 `data/*` 被 gitignore → **新克隆的仓库没有知识库**，
   工具会返回"未构建"，需要跑一次 rag_lab 导出（这是有意的：工件可再生，不该入库）。
2. 关键词模式是降级路径，评估里它的 recall@5 是 0.944（比混合低）；
   也就是说**不配 embedding 也能用，但效果略差**——工具返回里会说明。
3. 中文分词用字符 2-gram（零依赖的代价）：专有名词准，但语义泛化不如真分词。
